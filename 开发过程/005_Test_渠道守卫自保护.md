# 渠道仓守卫自保护记录

## 背景

飞书候选的运行时权限修复和包卫生门禁已经存在，但缺少能证明这些保护不可被无声撤掉的自动测试。
同时，组件测试可以被 `skip` 或 `only` 关闭而根门禁继续报绿。

本轮只改门禁与测试，不修改飞书或微信的收发消息、凭据、C4、生命周期和版本兼容行为。

## 实现

1. 根门禁扫描全部 Git 跟踪测试，拒绝 `skip`、`todo`、`only`、`xit`、`xdescribe` 和 Jest 路径忽略配置。
2. 飞书运行时测试真实启动 `src/index.js`，证明既存 `0755` 数据目录会被收紧到 `0700`。
3. 飞书包门禁使用临时 Git 仓库，分别证明未跟踪文件和 `/Users/...` 私人路径会被拒绝。
4. 根 `verify` 改为运行完整 `npm test`，确保新增根级门禁测试不是孤立文件。
5. 微信候选 rebase 到新的飞书守卫基线；微信组件目录及其专属门禁相对原锁定提交逐字未变。
