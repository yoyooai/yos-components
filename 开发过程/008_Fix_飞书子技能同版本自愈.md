# 飞书子技能同版本自愈

## 背景

飞书安装依赖 `lark-cli` 和 27 个配套子技能。npm 全局安装与 GitHub Release
制品下载是两条不同链路：前者成功不代表后者完整。旧流程在下载中断后留下
缺失文件，而同版本 `yos upgrade feishu` 又直接返回“已是最新”，无法自愈。

## 实现

- `SKILL.md` 显式声明 `repair` 钩子，供 Core 在同版本检查时调用。
- repair 与安装、升级复用同一个实现，逐项核对 27 个子技能。
- GitHub Release 下载采用 3 次有限重试和 120 秒单次超时；npm 全局安装采用
  独立的 180 秒超时。
- npm 失败返回 `feishu_lark_cli_npm_install_failed`，GitHub 制品下载失败返回
  `feishu_subskills_fetch_failed`，并分别给出阶段与修复建议。
- 被动修复不修改凭据和渠道访问策略，只同步既有凭据到完整的 lark-cli 安装。

## 边界与取舍

本轮没有把第三方子技能镜像进 YOS 货架。镜像会新增制品来源、不可变版本和
发布合同，不能和一次安装自愈修复混做。当前通过有限重试、超时和完整性核验
降低网络失败；自有镜像另立供应链任务。

## 验证

- 测试覆盖 27 项完整性识别、两次失败后成功、GitHub 失败、npm 失败和 repair
  声明接线。
- Core 的同版本 CLI 端到端测试证明 repair 失败会退出非零且不再假报健康。
- 最终门禁和突变结果在交付说明中记录。本轮不合并、不打标签、不发布，也不
  修改生产服务器。
