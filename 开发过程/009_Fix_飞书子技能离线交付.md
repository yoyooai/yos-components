# TD-159 飞书子技能离线交付

## 背景

飞书安装通过 `npx xc-skills` 从 GitHub 现拉 27 个静态子技能。在国内慢链路上，直接子进程超时后后代仍继续写安装目录，导致产品先报失败、稍后文件又自行齐全，并可能与用户立即发起的修复并发写同一目录。

## 决策

- 将 `larksuite/cli` `v1.0.81` 的 27 个子技能随组件包交付，正常安装不访问 GitHub。
- `package.json#larkCli.version` 是运行时唯一版本源；来源清单记录 tag、commit、归档 SHA-256 和许可证证据。
- vendor 缺失或不完整时保留网络兜底；兜底命令运行在独立进程组中，超时、失败或成功返回后均先清理仍存活的后代，再检查每个目录的 `SKILL.md`。
- 保留 `run` 注入点，不修改 lark-cli 二进制的 npm 安装路径、超时和重试次数。

## 未采用

- 不延长 120 秒超时，也不增加三次尝试。延长只会增加等待，不能消除客户机对 GitHub 的依赖。
- 不把完整性口径放松成只数目录；仍要求 27 个 `SKILL.md` 全部存在。

- tag：`v1.0.81`
- commit：`003d0f42f84d3799c62f2a666fb0ddf4084283c7`
- 许可证：MIT，允许复制与再分发，原许可证随包保留。
- 完整归档 SHA-256：`0c5f04972157582aa7227449da75e39d3b37698f372783952972c7f973dba0f4`

## 验证

- vendor 树与完整上游归档的 `skills/` 逐文件 `diff -r` 无差异：27 个目录、458 个技能文件。
- 定向测试覆盖本地零网络、版本不一致拒绝、网络写入完成后再判、负 PID 进程组清理、超时和成功返回后的顽固孙进程停止写盘。
- 组件包压缩后约 1.35MB，包含 458 个技能文件、来源清单和 MIT 许可证。

## 返修收口（2026-08-14）

- 两条真实进程测试不再依赖固定冷启动时间：孙进程先写入就绪标记，测试确认标记存在后才启动超时/成功清理判定，消除并发门禁下的偶发红灯。
- 飞书 npm 包门禁现在直接复用产品中的 27 项唯一清单，要求包清单包含 vendor 许可证、来源清单和每个子技能的 `SKILL.md`，并交叉核对 `source.json#fileCount`。
- 反证覆盖整棵 vendor 缺失、单个子技能被 npm 排除、来源计数不一致；仓库测试底线从 73 抬到 76，包策略关键测试下限从 1 抬到 5。

## 守门收口（TD-163）

- 校验只读取仓内 `source.json`，不访问 GitHub，也不改变 458 个 vendor 文件或飞书组件自身的 `provenance/upstream.json`。
- 仓库测试底线 76→77，包策略关键测试下限 5→6。
